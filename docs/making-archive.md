# SW2.x 能力値作成ログの分割

能力値作成の現行ログを一定件数に抑え、古い投稿を別ファイルに保存します。
SW2.5・SW2.0で共通の処理を使い、既存の行形式、投稿番号、
`?mode=making&num=123-2`のような作成結果URLを維持します。

## 設置と設定

両システムの`config-default.pl`、`making.pl`、`list-making.pl`、
新規の`_core/lib/sw2/making-log.pl`を一緒に更新してください。
テンプレートの変更や追加のCPANモジュールは不要です。

既定では、現行ログが2,000件に達した時点で最古の1,000件を退避します。
現行ログには1,000〜1,999件を保持します。投稿が少ない間は1,000件未満でも動作します。
設定を変更する場合は、使用するシステムの`config.cgi`の`package set`内に追記します。

```perl
our $making_max = 0;
our $making_archive_keep = 1000;
our $making_archive_unit = 1000;
```

現行ログが`making_archive_keep + making_archive_unit`件に達するたびに、
最古の`making_archive_unit`件を退避します。
両方を0にすると自動退避を停止し、既存の過去ログは引き続き検索できます。
両方とも正の整数、または両方とも0にしてください。

`making_max`が正数の場合は従来の保存上限を優先し、古い投稿を削除して自動退避しません。
全ログを保存する運用では`making_max = 0`にしてください。

保存先は`$set::makelist`に`.archive`を付けたディレクトリです。必要になった時点で自動作成します。

```text
sw2.5/data/makelist.cgi
sw2.5/data/makelist.cgi.lock
sw2.5/data/makelist.cgi.archive/
  makelist-0000000001-0000001000.cgi
  makelist-0000001001-0000002000.cgi
```

ファイル名には実際の投稿番号の最小値・最大値を使います。欠番があっても構いません。
現行ログは投稿番号の降順である必要があります。
過去ログはこの処理だけで管理し、作成後に変更・削除・手動追加しないでください。
バックアップ・復元時は、現行ログと過去ログディレクトリを同じ時点の組として扱ってください。

## 既存の大きなログを初回分割する

通常の投稿でも自動分割しますが、初回は現行ログを全件メモリに読み込みます。
大きなログは、バックアップを取得して投稿を一時停止し、Web側の更新と設定を済ませたうえで、
リポジトリのルートから次のコマンドで事前分割することを勧めます。

```sh
perl tools/archive-making.pl sw2.5/data/makelist.cgi 1000 1000
```

SW2.0ではログのパスを`sw2.0/data/makelist.cgi`に変更してください。
末尾の2つの引数は、現行に残す件数と分割単位です。省略時は両方1,000です。
Web側で設定値を変更した場合は、コマンドの件数も合わせてください。

CLIもWeb側と同じロックを使用し、新規投稿を作らずに既存ログを分割します。
実行ユーザーとWeb側のCGIには、現行ログ、ロックファイル、親ディレクトリ、過去ログへの
必要な読み書き権限が必要です。可能ならCGIと同じユーザーで実行してください。

分割中は元ログと退避先が同時に存在するため、バックアップとは別に元ログと同程度の空き容量が必要です。
処理時間と必要メモリは、件数だけでなくファイル容量やサーバー環境によって変わります。
10万件を既定設定で分割すると、現行1,000件と過去ログ99ファイルになります。
分割後に過去の番号リンクと検索を確認してから投稿を再開してください。

## 検索と保存の動作

- 通常一覧、マイリスト、ID指定、タグ検索は、現行と全過去ログを新しい順に検索します。
- 表示する10件と11件目の有無を調べ、次ページがあると分かれば読み込みを止めます。
- 投稿番号指定では、ファイル名の番号範囲で過去ログの読み込み先を絞ります。
- 共有ロック中に現行ログと過去ログ一覧を取得し、過去ログ本文の検索中は投稿をロックしません。
- 連投制限の期間が過去ログまで及ぶ場合は、その過去ログも確認します。
- 最古のブロックから一時ファイル経由で退避し、保存成功後に現行ログを置き換えます。
  更新途中で停止した場合は検索時に重複を除外し、次回の退避時に同じ内容の保存済みファイルを再利用します。
  内容が違う過去ログや重複する番号範囲があれば上書きせずに停止します。
  退避途中で分割単位を変えて範囲が重複した場合は、元の単位に戻して再実行してください。
- 一時ファイルを作成できない場合は、内部パスを表示せずHTTP 500のエラー画面を返します。

検索条件に合う投稿が少ない場合や古いページへのアクセスでは、全過去ログを走査します。
検索用インデックスは作成しません。
停電やストレージ自体の障害に対する永続性保証は追加していないため、バックアップは継続してください。

## テスト

```sh
prove -v t/making-log.t t/making-integration.t
```

分割・検索・連投制限・同時投稿・中断後の再実行・HTTP 500の表示を、一時ディレクトリ内のログで検証します。
